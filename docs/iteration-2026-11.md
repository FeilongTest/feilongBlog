# 第二轮功能迭代

本轮继续保留上一轮安全、头像、SEO 修复，新增以下功能。代码位于分支 `fix/security-media-seo`，生产环境尚未部署。

## 写作与发布

- 文章编辑本机草稿：输入停止 750ms 后自动保存，按管理员账号和文章 ID 分开存放。
- 新建文章与已有文章分别保存，刷新后显示恢复/丢弃入口；保留 7 天。不自动覆盖服务器文章。
- 离开编辑页前提示，保存失败时保留草稿，存储空间不足时显示失败提示。
- 发布过程中阻止重复提交；创建接口返回文章 ID，发布后进入该文章编辑页面，后续保存使用更新接口。
- 修复可选文章 ID 的判断，避免把新建页当成 `NaN` 文章；修复保存成功响应没有有效提示的问题。
- 编辑/新增切换不再强制刷新整站，异步加载有时序检查；加载失败时暂停编辑，避免覆盖原文。
- Markdown 编辑器改为按需加载，Vditor 的运行时资源打包到同域 `web/vendor/vditor/`，避免编辑器初始化依赖外部 CDN。

草稿是浏览器本地副本，不是服务器备份：清除站点数据、换设备或超过保留时间会失效。两种内容格式各保留自己的编辑缓冲，不自动互相转换；切换格式后发布的是当前格式内容。

## 阅读与归档

- 归档页可按标题关键词和年份组合筛选，条件写入 URL，刷新和分享保留条件。
- 筛选结果显示数量，支持一键清除和无结果提示；继续沿用归档页 canonical，避免索引筛选组合。
- 文章显示字词数与预计阅读用时（中文约 300 字/分钟、英文约 200 词/分钟）。
- 增加复制文章链接和浏览器支持时的系统分享入口。
- 代码复制和文章链接复制共用兼容处理；权限被拒绝时不再产生未处理异常，并明确提示手动复制。

## 信息流性能

普通文章的公开列表接口增加 `summary`，不再把整篇正文发送到信息流；纯文本动态继续保留正文，文章详情与后台编辑仍返回全文。这是公开列表响应的调整，其他调用方如需正文应使用详情接口。

前端兼容没有 `summary` 的旧版 API。首页不再为摘要加载完整 Markdown 解析器，完整渲染留在文章详情页。

本轮普通富文本编辑页的构建 chunk 从约 1,123 KB 拆为约 826 KB；Markdown 编辑器约 295 KB，打开 Markdown 编辑器时再加载。Vditor 同域资源约 23 MB（磁盘未压缩），仅按需请求，不是首页一次性下载；部署需连同 `vendor/` 目录一起上传。

- `go test ./...` 与 `go vet ./...` 通过；新增文章 ID 回传和轻量信息流契约回归。

## 部署

使用第二轮完整 ARM64 包，它包含前一轮全部修复及本轮功能。后端创建接口与轻量摘要有调整，建议前后端一起更新，并保留旧哈希静态资源供已打开页面使用。按 [部署说明](maintenance-2026-11.md) 操作。

本轮未新增持久化字段，`summary` 仅为响应字段、不写入数据库。本地草稿不需要数据库表。

Cloudflare 的百度抓取限制和缺失原图仍需要账户或原始文件处理，部署本轮代码不会自动解决这两项。

## 后续建议

1. 优先完成生产环境验收与百度抓取修复，建立自动部署和回归流程。
2. 有稳定需求后，再加入服务器草稿与历史版本，支持跨设备恢复及内容误改回滚。
3. 内容继续增长后，引入标签和数据库支持的全文搜索；避免直接用全文 `%LIKE%` 扫描替代检索方案。
